# HRMS API Contract

Owner: Backend Intern 3. Status: draft v1 (Day 1).
Any change must be written here and announced to the team the same day.

Base URL: `http://localhost:<PORT>/api`
Auth: `Authorization: Bearer <JWT>` on every endpoint except login, forgot-password, reset-password and health.
Roles: **A** = Admin, **M** = Manager, **E** = Employee.

## 1. Response format

Success:
```json
{ "success": true, "data": {} }
```

Error:
```json
{
  "success": false,
  "message": "Validation failed",
  "errors": [{ "field": "email", "message": "Email already exists" }]
}
```

| Status | Meaning |
| --- | --- |
| 200 / 201 | Success / created |
| 400 | Invalid input |
| 401 | Not logged in or invalid/expired token |
| 403 | Logged in but not allowed |
| 404 | Not found |
| 409 | Conflict (duplicate, open check-in) |
| 500 | Unexpected error (friendly message) |

The server validates everything, even if the frontend also validates.

## 14. Details for endpoints built by Backend 3 (implemented)

Extra endpoints added beyond the draft list: `GET /auth/me`, `PATCH /notifications/read-all`, `POST /onboarding/hire`, `PATCH /onboarding/:id`.
Dates in requests use `YYYY-MM-DD`. Reports default to the first day of this month up to today.

**GET /dashboard/summary** (Admin = company, Manager = own team, Employee = personal)

Admin/Manager:
```json
{ "success": true, "data": {
  "scope": "company", "activeEmployees": 6, "checkedInToday": 5, "lateToday": 1,
  "onLeaveToday": 0, "absentToday": 1, "pendingLeaveRequests": 3,
  "pendingLeaveList": [{ "id": 1, "employeeName": "", "employeeCode": "", "leaveType": "", "startDate": "", "endDate": "" }],
  "unreadNotifications": 0 } }
```
Employee:
```json
{ "success": true, "data": { "scope": "personal", "todayAttendance": { "checkIn": "", "checkOut": null, "status": "Present" },
  "leaveBalances": [{ "leaveType": "Annual", "remainingDays": 14 }], "myPendingLeaveRequests": 0, "unreadNotifications": 0 } }
```

**GET /notifications?unread=true** returns `[{ id, message, type, isRead, createdAt }]`. Types: `LEAVE_REQUEST`, `LEAVE_DECISION`, `ATTENDANCE_ALERT`, `ANNOUNCEMENT`.

**POST /announcements** body `{ "title": "", "body": "" }`. All other active users get an in-app notification.

**GET /reports/attendance?from=&to=&employeeId=&departmentId=** (Admin, Manager team). Returns `totals` and `rows` with presentDays, lateDays, earlyDepartures, leaveDays, absentDays, workedHours, overtimeHours.
**GET /reports/leave?from=&to=&employeeId=&departmentId=&leaveTypeId=&status=**. Returns `summary` and `rows`.
**GET /reports/departments**. Returns employees per department and per designation.

**Recruitment**
- `POST /vacancies` `{ title, departmentId, description }`; `PATCH /vacancies/:id` any of those plus `status` (Open or Closed).
- `POST /applicants` `{ vacancyId, name, email, phone? }` (409 if vacancy is closed); `PATCH /applicants/:id/stage` `{ "stage": "Applied|Interview|Selected|Rejected" }`.
- `POST /interviews` `{ applicantId, scheduledAt (ISO), interviewer, notes? }` (moves an Applied applicant to Interview).
- `POST /onboarding/hire` `{ applicantId, departmentId, designationId, branchId, joiningDate }`. Applicant must be Selected. Creates the employee (status Probation, next EMP code), a 90-day probation record and the onboarding checklist. Does not create a login.
- `GET /onboarding?employeeId=`, `PATCH /onboarding/:id` `{ done?, documentName? }`.
- `GET /probation?employeeId=`, `POST /probation` `{ employeeId, startDate, endDate, status? }`.

**POST /notifications/attendance-alerts/run** (Admin). NOT-3: creates in-app `ATTENDANCE_ALERT` notifications for late arrivals today and for employees who have not checked in (only after work start + grace minutes, and not for approved leave). Recipients: all Admins and the employee's reporting manager (if that person is a Manager or Admin). The same alert is never created twice per day. The server also runs this automatically every 15 minutes on weekdays (turn off with `ATTENDANCE_ALERTS_AUTO=false`).
Response: `{ "skipped": null, "lateAlerts": 1, "absentAlerts": 1, "absentChecked": true, "notificationsCreated": 4 }`

**POST /attendance-alerts/run** (Admin). Response: `{ "date": "2026-10-26", "late": 1, "absent": 1, "created": 4 }`.
Late and absent employees notify all Admins and the employee's reporting manager. The same alert is never sent twice on the same day, so running again returns `created: 0`. Weekends return `skipped`. A scheduled job runs the same check every 15 minutes after `ALERT_CHECK_TIME` (default 10:00). Notification type: `ATTENDANCE_ALERT`.
